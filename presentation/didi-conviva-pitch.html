02 · Station Agent

Station Agent – Definition & Key Insight

Airport/railway use case is highly complex — boundary ambiguity, time inference, and vendor API constraints.

1 · Unclear boundary

Overlap with the Personalization Agent makes routing hard.

"I need to go to the Beijing International Airport tomorrow at 10 AM, book a 7-seat SUV"

2 · Time inference logic

The station agent must cross-check ticket platforms for flight/train status — international vs. domestic flights demand different time-inference logics.

  • International flight → arrive 2 hrs early from home
  • Domestic flight → arrive 1 hr early at the airport
  • Train → arrive half an hour early at the railway station

All mean different set-off time from home.

3 · Missing 3rd-party tool-calling capabilities

Standardize user query to match Vendor's API input parameter.

● What we did to reduce the 30% false positive rate

  • Query collection & prompt rewriting → false positives reduced to almost zero
  • Adjusted boundary between Station and main ride-hailing agent
  • New rule: all three hailing elements present → skip tool-calling and book directly
  • Reduced unnecessary clarification and routing — session time reduced by 25%
